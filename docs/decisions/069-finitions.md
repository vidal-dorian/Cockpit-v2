## Contexte

La 064 garde trois finitions et en écarte trois. S29 montre les étapes d'un run comme une barre de progression : les étapes faites, celle qui attend, puis les étapes **à venir** de l'équipe, grisées et numérotées, et une dernière ligne « PR ». Cockpit ne sait pas aujourd'hui quelles étapes viendront : un run ne garde pas son équipe (seul un lancement cloud garde son nom, `cloud_launches.team`), et l'équipe est un fichier du repo (`.claude/team.md` ou `.claude/teams/<nom>.md`) que seul GitHub sert. La relire à chaque affichage coûterait un appel GitHub par page et serait parfois faux : le gel d'une app existante ([050](050-figer-l-existant.md)) ne garde que deux étapes, quelle que soit l'équipe. Celui qui sait, c'est Claude : `/dev-us` lit l'équipe avant la première étape. Il la dit donc à `start_run`.

## Les choix

| # | Question | Décision |
|---|---|---|
| A | D'où viennent les étapes à venir ? | `start_run` reçoit **`steps`**, facultatif : les noms des agents de l'équipe que le run va suivre, dans l'ordre (de 1 à 20, chacun au format d'un nom d'agent, 029), une fois par étape (une boucle n'est pas déroulée ; pour une US de reprise, les deux étapes du gel, 050). Gardé sur le run (`runs.planned_steps`, `jsonb`, nul quand absent). **Aucun appel GitHub.** Sans `steps` (un `/dev-us` pas encore mis à jour dans le repo), le run n'a pas d'étapes à venir : la page montre les étapes signalées, comme avant |
| B | Lesquelles sont à venir ? | `GET /api/runs/:id` rend **`upcomingSteps`** : sur un run en cours, les étapes du plan qui suivent la dernière occurrence, dans le plan, de l'agent de la dernière étape signalée ; sans étape signalée, tout le plan ; un agent absent du plan, ou un run fini : `[]`. Ainsi une boucle (`developer` refait après `reviewer`) remontre `reviewer` à venir |
| C | Les lignes (S29) | Dans « Les étapes · en direct » : les étapes signalées comme aujourd'hui, avec à droite **l'heure de début** (`9:02`, l'heure locale, comme le Journal) ; l'étape qui attend une réponse dit « attend ta réponse **depuis 4 min** » (le temps depuis la question en attente, `elapsed`). Puis chaque étape à venir, grisée, avec son **numéro** de rang dans la liste et « à venir » (les `does` des équipes sont en anglais : pas de phrase de l'écran inventée). Enfin la ligne **« PR · Claude pousse la branche et ouvre la PR »**, toujours la dernière tant que le run tourne, numérotée et grisée ; cochée « PR #n ouverte » quand l'US est passée en revue pendant le run (`link_pull_request`). La ligne de la branche gagne la durée du run en cours : « branche … · cloud · 16 min » |
| D | « Pourquoi Claude demande » : le champ | `ask_user` reçoit **`context`**, facultatif, de 1 à 1 000 caractères : ce qui est fait et ce que la réponse décide. Gardé sur la question (`questions.context`). La question garde aussi **l'agent de l'étape ouverte** du run au moment de la demande (`questions.agent`, la plus récente si plusieurs, nul sans étape ouverte), lu par Cockpit, pas envoyé par Claude |
| E | Où le bloc se montre | Une carte « Pourquoi Claude demande » sous la question, avec le contexte : dans le panneau de la question du run (S29) et dans celui de l'accueil (S00a, et donc aussi pour la question d'un run de nuit en pause, N2). Dans l'accueil, la ligne sous la question devient **« US 42 · étape developer · Run 17 ↗ »** (« US 42 » mène à l'US, « Run 17 ↗ » au run ; « étape … » omis sans agent), dans la carte quand elle est là, à sa place sinon. Sans contexte, **pas de carte**. `GET /api/runs/:id` et `GET /api/home` rendent `context` et `agent` |
| F | `/dev-us` | La compétence du catalogue dit de passer `steps` à `start_run` et `context` à `ask_user` ; `npm run catalog:history` ajoute son empreinte (049), donc « Mettre à jour » la propose aux repos déjà préparés |
| G | La carte du Kanban (S00b) | Un clic sur une carte **d'US** ou **d'idée** (colonne Idées) l'ouvre dans le panneau de droite ; le tableau reste visible (la coque fait de la place au panneau, 045). La carte reste un lien, vers la même page avec **`?us=<id>`** ou **`?ticket=<id>`** : un rechargement garde le panneau ouvert, chaque clic est une entrée d'historique (Précédent revient à l'état d'avant, le tableau seul après une carte), Ctrl-clic ouvre un onglet. La carte ouverte est marquée (`aria-current`) et un nouveau clic la ferme. Un `id` qui n'est pas une carte du tableau n'ouvre rien. Échap ferme le panneau (sauf pendant un formulaire du panneau) et rend le focus à la carte. La phrase devient « Pas de glisser-déposer : un clic ouvre la carte à droite. » |
| H | Le panneau d'une carte | **Rien de neuf, les panneaux existants** : pour une US, le panneau de décisions de sa page (`StoryDecisions`, 018 : Valider, Développer avec Claude, Relire sur GitHub…), avec en tête « US 42 · … », le lien **« Ouvrir l'US »** et, pour une US en cours, « Run n ↗ » ; pour une idée, le panneau de l'onglet Tickets (`TicketPanel`, 055 : « Ouvrir le ticket », Modifier, Supprimer), sans compteur |
| I | 9.5 B : ce qui est retiré | **Seul l'index `docs/ecrans/README.md` change** (la colonne « À trancher » de S10, S14 et S45), plus la liste de la 045. Les PNG et HTML ne sont pas retouchés : ils sont l'export du canevas validé, un HTML modifié ne correspondrait plus à son PNG, et la règle de l'index « la décision l'emporte » suffit. Retirés : les filtres de S10 (le champ, « Tous », « À toi », « Claude travaille », « Non préparés », « Archivés », « Trier ») sauf « Favoris » (15.3 C), et « Accès donnés à Claude » de S45 |
| J | Les filtres de l'onglet Tickets | **Gardés.** La loupe, « Ouverts », « Nouveaux » et « Étiquette » de S14 sont construits depuis la 11.2 (055 F) ; la 064 9.5 B reprend la liste de la 045, écrite avant la 11.2. Les retirer supprimerait une fonction décidée et construite, ce que la 064 ne dit pas : l'index note que rien n'est retiré de S14. *À confirmer à la relecture.* |

## Limites connues

- **Les étapes à venir sont celles que Claude annonce** : Cockpit ne vérifie pas `steps` contre le fichier d'équipe du repo. Une étape signalée hors du plan efface les étapes à venir jusqu'à la suivante qui y est.
- **Pas de phrase pour une étape à venir** : « à venir » à la place de « relira le diff avec un regard neuf » (S29). Une phrase française par étape demanderait de la faire écrire à Claude.
- **Les branches en parallèle** (064 E6 A) ne sont pas construites : le plan est une liste, pas un graphe.
- **La carte d'une US en cours** ne montre toujours pas « Run 17 · developer » (S00b) : le panneau donne le lien du run.
